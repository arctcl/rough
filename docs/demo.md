# Демо-проект (шаблон интеграции)

Живой пример — в папке `example/` (отдельный Go-модуль, `go build` + `go run . -tui`).
Здесь — как это устроено и как повторить у себя.

## Проект пользователя — максимум 4 строчки кода

```go
// main.go
package main

import (
	"embed"

	"rough"

	_ "example/rough/plugins" // 2. вот мои плагины
)

//go:embed rough
var roughDir embed.FS // 3. вот папка с html/темами/данными (вшивается в бинарник)

func main() {
	rough.TUI(roughDir) // 4. один вызов
}
```

Пользователь делает всего 4 вещи:
1. `import "rough"` — подключил движок;
2. `_ "example/rough/plugins"` — показал, где его плагины (Go-код, вшивается при сборке);
3. `//go:embed rough` — вшил папку с данными интерфейса;
4. `rough.TUI(roughDir)` — запустил.

## Структура проекта

```
myproject\
  go.mod                  # require rough + replace rough => ../rough
  main.go                 # 4 строчки выше
  rough\                  # ВСЁ про проект: данные + плагины (вшивается в бинарник)
    tiles.json            # страницы и тайлы
    tiles\*.html          # вёрстка тайлов
    themes\*.json         # темы
    plugins\              # плагины: свои или «линк» на готовые из корня репозитория
      plugins.go          # агрегатор: перечисляет плагины
```

**Библиотека (rough) = только движок.** Внутри неё НЕТ плагинов и тем — всё это
живёт в твоём проекте в папке `rough/`. Готовые плагины (`cat`, `hello`, `nyan`)
лежат в корне репозитория в папке `plugins/` — в проекте на них можно сослаться
одним импортом (как в `example/`), либо скопировать к себе и допилить. При сборке
движок + плагины + папка `rough/` сливаются в **один исполняемый файл**.
На проде ничего снаружи не нужно.

## Как это работает

```
go build
  → компилятор кладёт в бинарник: движок + твои плагины + папку rough/ (embed)
  → при старте init() каждого плагина регистрирует его в реестре движка
  → rough.TUI() берёт из вшитой папки: tiles.json, html, темы
  → клик по кнопке action="имя:..." → движок достаёт плагин из реестра → вызывает
```

Плагины не «ищутся» — они сами записываются в реестр при старте (`init()` + `AddPlugin`).

## Плагины

Единый контракт — юникс-команда: строки на входе, строки на выходе.
Готовые плагины — в корне репозитория `plugins/` (`cat`, `hello`, `nyan`-анимация).

Пример своего плагина (или копия готового):

```go
// myproject/rough/plugins/hello/hello.go
package hello

import (
	"strings"

	"rough"
)

func init() {
	rough.AddPlugin("hello", func(in []string, args []string) ([]string, error) {
		who := "мир"
		if len(args) > 0 {
			who = strings.Join(args, ":")
		}
		return []string{"привет, " + who + "!"}, nil
	})
}
```

Агрегатор перечисляет свои плагины. Можно «сослаться» на готовые из корня репозитория:

```go
// myproject/rough/plugins/plugins.go
package plugins

import _ "rough/plugins" // все готовые плагины репозитория (cat, hello, nyan)
```

В HTML плагин вызывается по имени, можно пайпом:

```html
<button action="hello">Поздороваться</button>
<button action="cat:/etc/hostname | hello">Показать hostname</button>
```

`| confirm` в конце — окно подтверждения («Выполнить?»).

## Данные интерфейса

### tiles.json — страницы и тайлы

```json
{
  "theme": "default",
  "паттерн": ["id", "x", "y", "w", "h", "файл"],
  "/main": [
    ["hello", "0%", "0%", "40%", "40%", "tiles/hello.html"]
  ]
}
```

Позиция тайла: `[id, x, y, w, h, файл]`. Число = пиксели (клетки), `%` = проценты.

### tiles/*.html — вёрстка тайла

```html
<h1 color="#ffcc00">Пример</h1>
<button action="hello">Поздороваться</button>
<input action="set:/etc/x.conf:level" label="level"/>   <!-- поле ввода -->
<a href="/other">→ Другая страница</a>                  <!-- переход -->
<plugin pipe="file:/tmp/cpu.log | bars:cpu=(\d+)" interval="1s"/>  <!-- живой график -->
```

`color` понимает: номер палитры терминала (`"3"`), hex (`"#ffcc00"`) или имя из темы.

### themes/*.json — темы

Копируешь из репозитория `themes/` или пишешь свою:

```json
{
  "name": "default",
  "symbols": { "tile_tl": "┌", "tile_tr": "┐", ... },
  "colors":  { "frame": "3", "title_fg": "#ffcc00", ... }
}
```

## Запуск

```
cd myproject
go run . -tui
```

## Безопасность

- **`run` запрещён движком** — из HTML нельзя выполнять произвольные команды.
- Команды в системе выполняет только **твой** плагин (твой код), если ты его написал.
- Плагины вшиты в бинарник: на проде их нельзя подменить без пересборки.
- Что умеет интерфейс = что умеет юзер, запустивший бинарник (права решает ОС).
