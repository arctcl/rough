# Кукингбук: HTML

Как из HTML-разметки получается готовый интерфейс в терминале. Идём от общего
к частному: сначала картинка целиком, потом по кусочкам, и каждый кусочек —
на живом примере, который можно вставить и попробовать.

---

## 1. Суть

Движок рисует страницы, на них раскладывает тайлы, а внутри тайлов располагает
обычный HTML — и интерфейс готов. Ты не пишешь код интерфейса и не собираешь
окна — ты пишешь HTML, а движок превращает его в клетки терминала и реагирует
на клики. Кнопка в HTML несёт команду, клик по кнопке выполняет команду, а её
результат показывается на экране — внизу в статус-строке или в специальном
блоке вывода.

---

## 2. Страницы и тайлы (tiles.json)

Интерфейс делится на **страницы** (роуты). Каждая страница — это набор **тайлов**,
прямоугольников с HTML внутри. Какие страницы существуют, какие тайлы на них стоят
и где именно — всё это описывается в одном файле `tiles.json`:

```json
{
  "theme": "default",
  "menu": [["Главная", "/main"]],
  "паттерн": ["id", "x", "y", "w", "h", "файл"],
  "/main": [
    ["left",  "0%", "0%", "50%", "100%", "tiles/left.html"],
    ["right", "50%", "0%", "50%", "100%", "tiles/right.html"]
  ]
}
```

Ключ `theme` задаёт тему из папки `themes/` (по умолчанию — `default`). Ключ `menu`
описывает вкладки внизу экрана: каждая вкладка — это пара «подпись и роут», по
которому она переключает страницу. Ключ `паттерн` — это схема строки тайла; его
можно не писать, потому что дефолтная схема ровно такая. А дальше идут страницы:
имя роута (например `/main`) и список его тайлов.

Каждый тайл — это массив из шести значений: `[id, x, y, w, h, файл]`. `id` — имя
тайла, которое видно на его рамке. `x`, `y`, `w`, `h` — позиция и размер: можно
писать проценты от экрана (`%`), клетки (`px`) или доли окна (`vw`/`vh`). И наконец
`файл` — путь к HTML-файлу тайла. Движок сам растягивает тайлы под размер
терминала: изменил окно — проценты пересчитались, и ничего не поплыло.

---

## 3. Первый тайл: текст и разметка

Всё, что написано в HTML тайла, рисуется как есть — теги при этом делают текст
осмысленным. Заголовок, абзац, пустая строка, жирный и курсив, центрирование,
линия и моноширинный блок:

```html
<h1>Заголовок</h1>
<p>Обычный абзац.</p>
<br/>                  <!-- пустая строка -->
<b>жирный</b> <i>курсив</i>
<center>по центру</center>
<div>блок текста</div>
<hr/>                  <!-- линия -->
<pre>
   моноширинный блок
   пробелы сохраняются
</pre>
```

Цвет указывается атрибутом `color` для текста и `bg` для фона. Доступен ввод hex,
но приветствуется ввод цвета из палитры с номером: так, если юзер сидит на арче
с перекрашенным терминалом и выбрал тему «терминал», ему будет круто — движок
возьмёт цвет прямо из его палитры, и другие темы будут применяться адекватно:

```html
<h1 color="#ffcc00">Жёлтый заголовок</h1>
<p bg="4">Синий фон</p>
```

## 4. Кнопка и команда (action)

Кнопка вызывает **команду** — ровно как команда в Linux. Формат простой:
`имя:арг1:арг2`. Имя — это плагин, аргументы отделяются двоеточием:

```html
<button action="hello">Поздороваться</button>
<button action="hello:мир">Поздороваться, мир</button>
<button action="cat:/etc/hostname">Показать hostname</button>
<button action="cat:/etc/os-release">Показать os-release</button>
```

Первая кнопка вызывает плагин `hello` без аргументов. Вторая — тот же `hello`, но
с аргументом `мир`. Третья и четвёртая — плагин `cat` с путём к файлу: `cat`
читает файл с диска и отдаёт его содержимое. Параметры можно задавать и флагами,
как в Linux (`cat --файл=/x`), и quick-позиционно, через двоеточие, — что именно
принимает плагин, определяется самим плагином, а узнать это всегда можно через
справку: кнопка `action="man:имя"` покажет описание. Результат команды без
атрибута `output` показывается в статус-строке внизу экрана.

---

## 5. Пайп: цепочки команд

Пайп `|` соединяет команды в цепочку: вывод одной команды идёт на вход следующей,
как в шелле. Например, взять хвост лога или отфильтровать строки конфига:

```html
<button action="cat:/var/log/app.log | tail:20">Хвост лога</button>
<button action="cat:/etc/x.conf | grep:^server | head:5">Серверы (5)</button>
```

Здесь `cat` читает файл и отдаёт строки, `grep` оставляет только нужные, а `head`
режет до первых пяти. Если на каком-то шаге случилась ошибка — пайп останавливается,
а сообщение об ошибке показывается в статус-строке.

---

## 6. Куда идёт результат: статус, блок, переменная

Результат команды можно показать тремя способами. Без атрибута `output` результат
просто уходит в статус-строку внизу. Если указать `output="id"` — результат
попадёт в блок `<div id="id">`, и этот блок может лежать где угодно: в этом тайле,
в соседнем или вообще на другой странице:

```html
<button action="man:ssh" output="out">Справка по ssh</button>
<!-- в любом тайле: -->
<div id="out"></div>
```

А если нужно запомнить результат и переиспользовать позже, пригодится плагин
`export`: он сохраняет вывод в переменную движка, а `$имя` в любом `action`
подставляет её значение. Запомнил хост один раз — и пользуешься им во всех
кнопках:

```html
<button action="ssh:root:srv1::hostname | export:host">Запомнить</button>
<button action="ssh:root:$host::uptime">Uptime на $host</button>
```

## 7. Поле ввода: юзер вводит значение

Поле ввода собирает команду из своего `action` и текста, который введёт юзер.
Клик по полю активирует его, юзер печатает, жмёт Enter — и движок склеивает
`action` с вводом через двоеточие и выполняет. Ввёл `ssh` в поле с `action="man:"` —
выполнится `man:ssh`; ввёл `100` в поле с `action="set:...:max_users:"` —
выполнится `set:...:max_users:100`:

```html
<input action="man:" label="Пакет"/>   <!-- ввёл ssh → man:ssh -->
<input action="set:/etc/app.conf:max_users:" label="Лимит"/>  <!-- ввёл 100 → set:...:100 -->
```

Esc отменяет ввод. И важный момент безопасности: ввод из поля — это всегда одно
значение, движок оборачивает его в кавычки, поэтому спецсимволы `|`, `:`, `$`
внутри ввода не работают как синтаксис. Ввести `cat | ssh:...` через поле нельзя —
это останется обычным текстом, а не командой.

## 8. Управление конфигами: чекбокс и выпадающий список

Для управления файлами вида `ключ=значение` есть два удобных элемента. Файл
`app.conf` выглядит так:

```
debug=1
logging=0
loglevel=info
```

**Чекбокс** — это галочка: клик по нему переключает значение ключа в файле
(0↔1, on↔off). Галочка ставится или снимается автоматически по текущему значению:

```html
<checkbox action="toggle:app.conf:debug">Отладка</checkbox>
<checkbox action="toggle:app.conf:logging">Логирование</checkbox>
```

**Выпадающий список** — это выбор одного значения из набора: выбранный вариант
дописывается к команде, и команда выполняется. Выбрал `debug` — выполнилось
`set:app.conf:loglevel:debug`:

```html
<select action="set:app.conf:loglevel" options="info:debug:trace" label="Уровень"/>
```

Списки умеют и вложенность: вариант с подменю записывается как `Метка [дети:варианты]`,
и подменю раскрывается справа от родителя:

```html
<select action="set:app.conf:theme"
        options="Тёмная:Светлая:Цветная [Красная:Зелёная:Синяя]" label="Тема"/>
```

## 9. Таблицы, картинки, ссылки

Таблица собирается из строк `<tr>` и ячеек `<td>` (обычные) и `<th>` (жирный
заголовок); колонки выравниваются по самой широкой ячейке. Картинка рисуется из
файла PPM P6 половинчатыми блоками, а ссылка переключает страницу на указанный
роут:

```html
<table>
  <tr><th>Сервис</th><th>Статус</th></tr>
  <tr><td>api</td><td>работает</td></tr>
  <tr><td>db</td><td>работает</td></tr>
</table>

<img src="/opt/app/logo.ppm"/>   <!-- картинка PPM P6 -->

<a href="/main">← На главную</a>  <!-- переход на страницу -->
```

---

## 10. Живой контент: plugin по таймеру

Тег `<plugin>` сам себя обновляет по таймеру — без всяких кликов. Интервал
задаётся атрибутом `interval` (если не задан — две секунды). Так в тайле живут
часы, график нагрузки или спарклайн:

```html
<plugin name="clock" interval="1s"/>                    <!-- часы -->
<plugin pipe="emu_cpu | chart:0:100:1:2:CPU" height="14" interval="2s"/>  <!-- график -->
<plugin pipe="cat:data.log | tail:10 | bars" interval="2s"/>              <!-- спарклайн -->
```

`chart` — живой столбчатый график с осями. Его параметры: `chart:МИН:МАКС[:ШИРИНА[:СЕКУНД[:ЗАГОЛОВОК]]]`.
Высота берётся из атрибута `height`, ширина — из тайла или колонки, так что график
сам подстраивается под место.

## 11. Собери панель: всё вместе

Соберём маленькую панель: одна страница, слева тайл с настройками, справа — тайл
вывода. Начинается всё с `tiles.json`:

```json
{
  "theme": "default",
  "menu": [["Панель", "/main"]],
  "/main": [
    ["cfg", "0%", "0%", "50%", "100%", "tiles/cfg.html"],
    ["out", "50%", "0%", "50%", "100%", "tiles/out.html"]
  ]
}
```

В тайле настроек живут чекбокс, выпадающий список, кнопка, которая показывает
конфиг, и поле ввода для справки. Всё это пишется в `tiles/cfg.html`:

```html
<h1>Настройки</h1>
<checkbox action="toggle:app.conf:debug">Отладка</checkbox>
<select action="set:app.conf:loglevel" options="info:debug:trace" label="Уровень"/>
<button action="cat:app.conf" output="out">Показать конфиг</button>
<input action="man:" output="out" label="Справка по плагину"/>
```

А в `tiles/out.html` — просто заголовок и приёмник вывода, куда падают результаты:

```html
<h1>Вывод</h1>
<div id="out"></div>
```

Готово: кнопки меняют конфиг, чекбоксы переключают флаги, а результат любой
команды показывается в правом тайле.

## 12. Шпаргалка: теги

| Тег | Что делает | Пример |
|---|---|---|
| текст | рисуется как есть | `Привет` |
| `<h1>` / `<p>` | заголовок / абзац | `<h1>Настройки</h1>` |
| `<br/>` | пустая строка | `<br/>` |
| `<b>` / `<i>` | жирный / курсив | `<b>x</b>` |
| `<center>` | по центру | `<center>x</center>` |
| `<div>` | блок | `<div>x</div>` |
| `<row>` | ряд колонок | `<row><div width="50%">…` |
| `<div width="%">` | колонка | `<div width="30%">x</div>` |
| `<div align="center">` | блок по центру | `<div align="center">…` |
| `<div id="id">` | приёмник вывода | `<div id="out"></div>` |
| `<hr/>` | линия | `<hr/>` |
| `<pre>` | моноширинный блок | `<pre>…</pre>` |
| `<button action>` | кнопка-команда | `<button action="cat:/x">` |
| `<input action label output>` | поле ввода | `<input action="man:" label="Пакет"/>` |
| `<checkbox action>` | переключатель | `<checkbox action="toggle:a.conf:debug">` |
| `<select action options label>` | выпадающий список | `<select action="set:…" options="a:b:c"/>` |
| `<table>` | таблица | `<table><tr><td>x</td></tr></table>` |
| `<img src>` | картинка PPM | `<img src="/opt/x.ppm"/>` |
| `<a href>` | переход на страницу | `<a href="/main">На главную</a>` |
| `<plugin name/pipe interval>` | живой контент | `<plugin name="clock" interval="1s"/>` |
| `output="id"` | куда вывести результат | `<button action="…" output="out">` |
| `| confirm` | подтверждение | `<button action="… | confirm">` |

## 13. Частые вопросы

**Куда делся результат?** Без `output` — в статус-строку внизу. С `output="id"` —
в блок `<div id="id">`.

**Почему у поля ввода `:` в конце action?** Потому что ввод приклеивается к action
последним аргументом: `man:` + `ssh` = `man:ssh`. Без `:` движок добавит сам.

**Можно ли через поле ввода выполнить свою команду?** Нет. Ввод — одно значение
(в кавычках), `|` и `:` в нём не работают как синтаксис.

**Как узнать, какие аргументы у плагина?** Кнопка `man:имя` покажет справку:
`<button action="man:ssh">Справка по ssh</button>`.

**Не работает кириллица?** Терминал должен быть UTF-8: Windows — `chcp 65001`
или Windows Terminal / VS Code.
