## 1. Раскладка экрана — `tiles.json`

`tiles.json` лежит в папке `rough/` проекта. Он описывает **страницы** (экраны)
и **тайлы** (прямоугольники) внутри каждой.

### 1.1 Формат файла

Сначала один раз объявляется **паттерн** — порядок полей в строках данных.
Потом — сами страницы. Ключ `theme` — имя темы, `menu` — вкладки.

```json
{
  "theme": "default",
  "menu": [
    ["Главная", "/main"],
    ["Настройки", "/cfg"]
  ],
  "pattern": ["id", "x", "y", "w", "h", "file"],
  "/main": [
    ["cfg",  "0%",  "0%",  "40%", "100%", "tiles/cfg.html"],
    ["out",  "40%", "0%",  "60%", "100%", "tiles/out.html"]
  ]
}
```

### 1.2 Паттерн

Строка тайла — массив значений в порядке полей из `pattern`.
По умолчанию (если `pattern` не задан): `["id","x","y","w","h","file"]`.

| Поле   | Что это                                  |
|--------|------------------------------------------|
| `id`   | имя тайла (показывается на рамке, используется для `output`) |
| `x`,`y`| позиция левого верхнего угла             |
| `w`,`h`| ширина и высота                          |
| `file` | путь к HTML-файлу тайла (относительный)  |

### 1.3 Координаты: проценты и пиксели

Размеры и позиции — **проценты** (от окна) или **пиксели** (клетки терминала).
Смешивать можно в любом сочетании.

```json
["cfg",  "0%",  "0%",  "40%", "100%", "tiles/cfg.html"],   <!-- 40% ширины -->
["side", "60%", "0",   "10",  "100%", "tiles/side.html"],  <!-- 10 клеток -->
```

При изменении размера терминала тайлы **растягиваются** по своим процентам —
ничего не ломается.

### 1.4 Вкладки (`menu`) и тема (`theme`)

- `menu` — список пар `[имя вкладки, роут]`. Вкладки рисуются внизу.
- `theme` — имя темы из папки `themes/*.json`.

## 2. HTML-разметка тайла — теги

Каждый тайл — обычный HTML-файл. Движок понимает свой набор тегов.

### 2.1 Текст и блоки

| Тег       | Что делает                                   |
|-----------|----------------------------------------------|
| `h1`      | заголовок (жирный, с отступами)              |
| `p`       | абзац                                        |
| `b` / `i` | жирный / курсив                              |
| `center`  | выравнивание по центру                       |
| `pre`     | моноширинный блок «как есть»                 |
| `br`      | перенос строки                               |
| `hr`      | горизонтальная линия на всю ширину           |
| `div`     | блок (группировка), может быть приёмником вывода |
| `row`     | строка с колонками (`div width="50%"` внутри) |

```html
<h1>Заголовок</h1>
<p>Обычный текст и <b>жирный</b>.</p>
<hr>
<center>по центру</center>
```

### 2.2 Цвета

Атрибуты `color` и `bg` у любого тега. Значение — имя из темы, `#rrggbb`,
номер палитры терминала или имя палитры (`red`).

```html
<p color="color_2" bg="#000000">зелёный текст на чёрном</p>
```

### 2.3 Управляющие теги (кликабельные)

| Тег        | Что делает                                        |
|------------|---------------------------------------------------|
| `button`   | кнопка, выполняет `action` по клику               |
| `a href`   | ссылка на другую страницу (роут)                  |
| `input`    | поле ввода, Enter выполняет `action`              |
| `checkbox` | чекбокс (состояние читается у плагина через `:get`) |
| `select`   | выпадающий список (варианты из `options`)         |
| `plugin`   | живой плагин по таймеру (см. раздел 10)           |

## 3. Действия — `action`

**Действие** — это вызов плагина (юникс-команды). Пишется в атрибуте `action`
у кнопки, поля, чекбокса, селекта.

```html
<button action="cat:/etc/hostname">Hostname</button>
<button action="ssh:root:srv1::uptime">Uptime</button>
```

### 3.1 Базовая форма

```
имя:арг1:арг2:арг3
```

`имя` — команда, `:` — разделитель аргументов.

### 3.2 Множественные `action` на одном элементе

Один элемент может нести несколько атрибутов `action` — выполнятся
**последовательно**, в один приёмник:

```html
<button action="clear" action="man:ssh" action="cat:/etc/hosts">справка и файл</button>
```

### 3.3 Async — действие в фоне (не блокирует интерфейс)

Атрибут **`async`** у кнопки запускает действие в **фоновой горутине**:
медленный плагин (ssh/curl/большой файл) **не морозит интерфейс** — можно
кликать и листать, пока он работает.

```html
<button async action="ssh:root:srv::apt upgrade && apt upgrade -y" output="out">Деплой</button>
```

Правила:
- Пока async-задача идёт — в приёмнике видно «running…», **повторный клик
  игнорируется** (защита от двойного запуска).
- **Ключ задачи = раскрытая команда** (после `$`-подстановки). Две одинаковые
  async-кнопки = одна задача.
- Когда готово — результат выводится в `output="id"` (или в статус-строку).
- Фоновая горутина **не трогает экран и состояние ядра** — только шлёт вывод
  по каналу. Поэтому рейсов нет, интерфейс не падает.
- `| confirm` с `async` пока не сочетается (выполнится синхронно).

### 3.4 Секретные последовательности клавиш (секретные коды)

Плагин может зарегистрировать **секретную последовательность клавиш** — при её
вводе движок выполнит действие или **откроет страницу**. В демо набери `ps+` —
откроется скрытая страница `/ps` с живым монитором горутин, а классический
конами-код откроет страницу `/konami`:

```
ps+              →   откроется страница /ps (секретный монитор горутин)
↑ ↑ ↓ ↓ ← → ← → B A → откроется страница /konami (пасхалка «GLHF mate!»)
```

Это не синтаксис HTML, а фича плагинов (см. cookbook-plugins §16): плагин
внедряет хук в движок через `rough.AddCheat(seq, action)` (действие) или
`rough.AddCheatRoute(seq, route)` (переход на страницу). В демо коды заданы
данными в `chch.json` через инжектор `chch` — без правки кода.

Кодировка последовательности: `'U','D','L','R'` — стрелки, буква/цифра — та
клавиша, `'+'` — плюс.

### 3.5 Отладка: плагин `ps`

Плагин `ps` показывает все горутины движка (id, статус, верхняя функция) и память.
Для постоянного отслеживания — `interval` + `async` (и `--track=1`, чтобы помечать
исчезнувшие как `DEAD`):

```html
<plugin pipe="ps --track=1" interval="1s" async/>
```

## 4. Аргументы плагина

У каждого плагина объявлены параметры (в Go-коде). Движок умеет три формы
ввода и их смесь.

### 4.1 Позиционные (двоеточиями)

По порядку объявления. `chart:МИН:МАКС[:ШИРИНА[:СЕКУНДЫ[:ЗАГОЛОВОК]]]`:

```
chart:0:100:1:2:CPU
```

Пустой слот `:` — параметр пропускается (берётся дефолт/флаг):

```
chart:0:100::2:CPU
```

### 4.2 Именованные (флаги)

Порядок не важен, можно несколько флагов в одном аргументе:

```
chart --min=0 --max=100 --title=CPU
```

### 4.3 Смесь

Пустой слот `:` заполняется флагом/дефолтом:

```
chart::100 --title=CPU
```

### 4.4 Правила

- Обязательный параметр без значения → **ошибка** (движок не запустится).
- Неизвестный флаг → **ошибка** (опечатка не проходит молча).
- **Последний параметр «глотает» остаток двоеточий** — удобно для команд
  с произвольным хвостом:

  ```
  ssh:user:host:67:docker compose down && up
  set:file:key:value:with:colons
  ```

### 4.5 Кавычки

`'...'` и `"..."` защищают спецсимволы. Внутри кавычек `:` и `|` — обычные
символы. Это и защита от инъекций, и способ передать разделитель:

```
sed:':':1
```

## 5. Пайпы — `|`

Пайп — конвейер: **выход одного шага → вход следующего** (как в Linux).

```html
<button action="cat:/var/log/app.log | grep:ERROR | head:5">ошибки</button>
```

- Каждый шаг — вызов плагина.
- Вывод последнего шага идёт в приёмник (статус-строка или тайл `output`).
- Плагин может быть и **источником** (без входа): `cat:`, `ssh:`, `curl:`.

---

## 6. Несколько действий — `&&` и `clear`

`&&` — несколько **независимых** пайпов, выполняются последовательно, каждый
своим выводом.

```
a && b && c
```

### 6.1 Склейка с `clear`

Если в цепочке есть `clear` — приёмник **очищается**, и каждый пайп **добавляет**
свой вывод (склейка, как `cat a b`). Без `clear` последний пайп перезаписывает.

```
clear && man:ssh && cat:/etc/hosts
```

Один пайп без `&&` — простое выполнение (перезапись приёмника).

---

## 7. Подтверждение — `| confirm`

`| confirm` в конце действия открывает **окно подтверждения**: Enter — да,
Esc — нет. Для опасных кнопок.

```html
<button action="ssh:root:srv1::apt update && apt upgrade -y | confirm">Обновить</button>
```

Пока окно открыто, остальные клики **заблокированы** — случайно не нажмёшь.

## 8. Переменные сессии — `$имя`

Движок хранит переменные (имя → значение). Запись — плагин `export`
(работает как `tee`: сохраняет и пропускает вывод дальше), подстановка —
движок в любом `action`.

```
ssh:root:srv1::hostname | export:host     <!-- запомнили хост -->
ssh:root:$host::uptime                    <!-- подставили -->
```

### 8.1 Формы подстановки

| Форма      | Что делает                                  |
|------------|---------------------------------------------|
| `$имя`     | подставить значение (`имя` — буквы/цифры/`_`) |
| `${имя}`   | то же, но имя отделено от соседей `{}`      |
| `${имя%пат}` | подставить, убрав **суффикс** `пат` (Bash: `${имя%пат}`) |
| `${имя#пат}` | подставить, убрав **префикс** `пат` (Bash: `${имя#пат}`) |
| `\$`       | литеральный знак `$`                        |
| `'...'`    | внутри кавычек подстановка НЕ выполняется (литерал) |
| неизвестная | пустая строка                               |

```html
<input action="ssh:$user:$host::$cmd" label="cmd"/>
```

Примеры `var%pat` (удобно отрезать расширение/хвост):

```
export:файл:... | export:f            <!-- f = "/var/log/app.log" -->
${f%.log}        → /var/log/app       <!-- убрали суффикс -->
${f#/var/}       → log/app.log        <!-- убрали префикс -->
```

> `$1`, `$2` (цифры) — НЕ переменные (чтобы не ломать `sed`/`awk`).
> `'...'` — защита: поле ввода оборачивает значение в кавычки, поэтому
> набранный `$имя` не подставится (нельзя прочитать переменную через ввод).

## 9. Вывод в тайл — `output="id"`

По умолчанию вывод команды идёт в **статус-строку** внизу. Чтобы направить его
в конкретный тайл — укажи `output="<id тайла>"`, а в HTML тайла поставь
блок-приёмник `<div id="<тот же id>"></div>`.

```html
<!-- тайл "input" -->
<input action="man:" output="out" label="Package"/>

<!-- тайл "out": движок рисует сюда вывод man -->
<div id="out"></div>
```

**Важно:** id в `output` и id в `<div>` должны совпадать. Результат рисуется
внутри блока при каждом кадре, пока не перезапишется новой командой.

## 10. Живые плагины — `<plugin interval>`

Тег `<plugin>` запускает плагин **по таймеру** (не по клику). Графики, часы,
мониторы — всё, что должно «жить» само.

```html
<plugin name="clock" interval="1s"/>
<plugin pipe="cat:/tmp/core_temp | cut::1 | bars" interval="1s"/>
```

| Атрибут          | Что делает                                   |
|------------------|----------------------------------------------|
| `name`           | имя плагина (или `pipe` — готовый пайп)      |
| `pipe`           | готовый пайп целиком                         |
| `interval`       | период запуска (`1s`, `500ms`)               |
| `updateanytime`  | если `1` — перезапускается и вне интервала   |
| `async`          | плагин-служба: живёт в своей горутине, кадр — по каналу |

**Живые плагины работают и на неактивных вкладках** — графики продолжают
собирать данные, пока пользователь на другой странице.

### 10.1 `async` — плагин-служба в своей горутине

С атрибутом **`async`** живой плагин становится «службой»: его пайп выполняется
в **фоновой горутине** (а не в главном цикле), а ядро показывает последний кадр.
Нужен, когда источник **медленный** (ssh/curl): выборка идёт в фоне и **не
морозит интерфейс**.

```html
<!-- медленный источник по ssh — в фоне, интерфейс не замирает -->
<plugin pipe="ssh:host::vmstat | cut::2" interval="1s" async/>
```

- Горутина не трогает экран и состояние ядра — только шлёт кадр по каналу
  → **без рейсов и падений**.
- Плагин-API (`Window`, `PluginKey`, `ThemeColor`, `SetVar`) защищён мьютексом —
  его можно вызывать из async-горутины.
- Быстрому локальному графику `async` не нужен (просто `interval`).

## 11. Поля ввода, чекбоксы, селекты

### 11.1 Поле ввода — `input`

```html
<input action="set:/opt/app/conf:max_users" label="max_users" output="out"/>
```

- Клик — активирует поле, ввод идёт прямо в него.
- Enter — выполняет `action`, подставляя введённое значение.
- Ввод оборачивается в кавычки (литерал) — **защита от инъекций**: поле не
  может протащить произвольную команду.
- `label` — подпись.

### 11.2 Чекбокс — `checkbox`

```html
<checkbox action="toggle:app.conf:logging">Логирование</checkbox>
```

- Состояние читается у плагина через `:get` (например `toggle:...:get`).
- `[x]` — включено, `[ ]` — выключено.

### 11.3 Выпадающий список — `select`

```html
<select action="opt:env" options="dev:prod:stage">Окружение</select>
```

- `options` — варианты через `:`.
- Подменю — вложенные уровни в `[квадратных скобках]`.
- Выбор записывает значение (плагин с памятью `opt` или файловый `set`).
- **Обязательно закрывай `</select>`** — иначе парсер «съест» следующий контент.

## 12. Темы — коротко

Темы — `themes/<имя>.json`: символы рамок/кнопок + цвета. Выбор — ключ
`theme` в `tiles.json`, переключение на лету — плагин `theme`:

```
theme:list    <!-- список тем -->
theme:ИМЯ     <!-- переключить -->
```

Цвета в HTML/теме: имя из темы, `#rrggbb`, номер палитры терминала, имя
палитры. Плагины берут свои цвета через `engine.ThemeColor`.

## Шпаргалка: полный путь данных

```
tiles.json ──► страницы/тайлы
tiles/*.html ─► RenderHTML ─► Buffer ─► diff-Blit на экран
клик ─► HitTest (хотзона) ─► action ─► PrepareAction (пайпы/&&/confirm/переменные)
     ─► RunSteps (шаг за шагом, каждый в recover) ─► вывод в output="id" или статус
```
