# How it works: как устроен движок

Короткий путь от `rough.TUI()` до картинки на экране. Сначала — два способа,
как вообще использовать движок, потом — что происходит внутри.

## 1. Как библиотека

Ты подключаешь rough как Go-модуль и сам собираешь бинарник со своими
страницами и плагинами. Всё вшивается через `embed` — на проде нет ни одного
внешнего файла:

```go
package main

import (
	"embed"

	"rough"
	_ "myproject/rough/plugins" // твои плагины (линк на готовые или свои)
)

//go:embed rough
var roughDir embed.FS

func main() { rough.TUI(roughDir) }
```

Твой проект — папка `/rough` с `tiles.json`, HTML тайлов, темами и агрегатором
плагинов (как собрать — [cookbook-project](cookbook-project.md)). CLI твоей
программы живёт как жил: интерфейс включается флагом `-tui`, без него
`rough.TUI()` просто возвращается и программа работает по-старому.

## 2. Как standalone-приложение

Готовый бинарник (например, собранный `example_project`) — запустил
и получил интерфейс, не написав ни строчки кода:

```
myapp.exe -tui
```

Движок читает `/rough` из embed: `tiles.json` (страницы/тайлы/menu) + тему +
HTML тайлов. Всё, что на экране, — результат работы плагинов и разметки.

Дальше — как всё устроено внутри.

## 3. Поток запуска

```
rough.TUI(embed.FS)
  → hasTUI(): есть ли -tui в аргументах? нет — возвращаемся (CLI живёт как жил)
  → Run(fsys): fs.Sub(fsys, "rough") → движок получает папку /rough проекта
      → LoadUI(fsys): tiles.json (страницы/тайлы/menu) + тема
      → CheckSyntax: action/plugin/ссылки существуют? ошибки — не стартуем
      → tcell.NewScreen() + Init() — берём терминал
      → главный цикл
```

## 4. Главный цикл

```
цикл:
  renderFrame(...)          # нарисовать кадр
  select:
    событие мыши/клавиши    # обработать, возможно перерисовать
    таймер 500мс            # перерисовать (живые плагины с interval)
```

События читаются в горутине и шлются в канал — цикл не блокируется.

## 5. Рендер кадра

```
renderFrame:
  bg = буфер w×h, залит фоном темы (bg/fg)
  шапка: " rough: /роут  [q] выход "
  для каждого тайла страницы:
    Rect(w,h) → координаты тайла в клетках (%/px)
    рамка символами темы (╔═╗...)
    inner-буфер → RenderHTML(html тайла)
    bg.Copy(inner)
  вкладки внизу (menu), статус-строка над ними
  подсветка под курсором мыши + фокус
  bg.Blit(tcell screen): сравнивает с прошлым кадром, на экран идут
    только ИЗМЕНЁННЫЕ клетки (дифф) → Show
```

## 6. HTML → клетки

```
ParseHTML (x/net/html) → наше дерево Node
RenderHTML:
  renderNode рекурсивно: для каждого тега — свой случай
  текст рисуется через flowState.put: сдвиг по ширине руны (uniseg),
    чтобы кириллица/иероглифы не наезжали
  button/a/input — рисуют себя + хотзону (кликабельную зону) с action/href/output
  row+div — колонки: каждый div в свой мини-буфер своей ширины,
    плагины внутри видят её через Window()
  div align=center — мини-буфер, центрирование по вертикали
```

## 7. События

- **Мышь**: движение → позиция (для подсветки квадратика); клик → hit-test по
  хотзонам → переход/поле/действие. Вся мышь — через единый `MouseEvent` и один
  обработчик: источники (десктоп через tcell, телетайп через `/dev/input/mice` на
  голом Linux VT) переводят свои данные в `MouseEvent`, движок их не различает.
- **Клавиши**: ввод в активное поле, фокус стрелками + Enter, вкладки
  (Tab/Ctrl+Tab/Ctrl+цифры), выход q/Esc/Ctrl+C.
- **Переменные**: `$имя` в action подставляется движком в момент выполнения шага;
  запись/накопление — резервные слова движка `export:имя` / `export:имя +=` в пайпе.
- **Таймер**: перерисовка — `<plugin interval="...">` обновляется.

## 8. Вывод команды в тайл

```
клик по кнопке/полю с output="id"
  → execAction(action, id)
  → RunSteps: пайп по шагам
  → если target задан → outputCache[id] = строки
  → renderFrame: тайл рендерит <div id="...">, а он подставляет outputCache[id]
без output → результат в statusMsg (статус-строка)
```

## 9. Плагины и пайпы

```
AddPlugin(name, fn) → реестр plugins map
клик по action="cat:x | grep:err"
  → PrepareAction → шаги (убирает confirm)
  → RunSteps: cat → строки → grep → строки → ...
  → confirm? окно «Выполнить?», Enter — выполняем
run запрещён движком — произвольный запуск невозможен
```

## 10. Тема

Тема (JSON) — символы рамок и цвета. `ResolveColor` понимает: имя из темы →
hex (#rrggbb) → номер палитры терминала → имя tcell. Устанавливается при старте.

## 11. Ключевые принципы

- движок = пустая оболочка; вся логика — в плагинах;
- один контракт `func(in, args) (out, err)` — всё через пайпы;
- всё нативно в Go, без внешних бинарников;
- всё вшивается в один бинарник (embed + плагины).
