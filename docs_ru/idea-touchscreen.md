# Идея: тачскрин (вырезано, лежит здесь)

> Статус: идея записана, код **вырезан** (2026-08-27). Вернуть можно из git-истории
> или переписать заново по этому описанию.

## Проблема

- Windows-тачскрин **не отдаёт касание как мышь** в терминалы (проверено:
  Windows Terminal, cmd, WSL Ubuntu). Обычная мышь при этом работает.
- Значит, движку не приходит позиция касания → «не тыкается».

## Решение (что было сделано, потом вырезано)

- Локальный источник **`people_windows_input_touchscreen.go`**: читает тачскрин
  напрямую через **Win32 Raw Input** (`RegisterRawInputDevices`, HID-отчёт тача),
  минуя терминал, и шлёт те же **`MouseEvent`**, что и остальные источники.
  - **тап** → клик (`Left=true`),
  - **движение пальцем** → drag (прокрутка),
  - всё идёт в единый `handleMouseEvent`.
- Проводка в `engine.go` — 2 строки:
  `touchCh := openTouchscreen(fail)` + `case me, ok := <-touchCh:`.
- Для Linux/Mac — пустышка `people_windows_input_touchscreen_stub.go` (возвращает `nil`).

## Чего НЕ успели / что учесть при возврате

1. **Разбор HID-отчёта был первой версией** — предполагал стандартный отчёт
   тачскрина с 16-битными X и Y (`hidCoordMax = 65535`), масштаб на весь экран.
   На реальном железе надо подгонять под конкретный отчёт.
2. **Маппинг пиксель → клетка** делался через размер шрифта консоли
   (`GetConsoleFontSize`) и размер экрана (`GetSystemMetrics`).
3. **Жест «свайп влево/вправо → переключение вкладки» НЕ был добавлен** — это
   отдельный слой жестов поверх `MouseEvent` (надо бы: быстрое горизонтальное
   перетаскивание → `nextRoute`).

## Почему локальный ловец, а не нативный для всех

- По SSH палец уже приходит как мышь (телефон-клиент шлёт мышиные события) —
  там обычный источник работает.
- Нативный ловец нужен **только локально**, потому что терминалы Windows не
  отдают касание как мышь.
