# Кукингбук: HTML

Справочник по тому, как движок рисует тайлы и что он ожидает от HTML и `tiles.json`.
Здесь не «примеры ради примеров», а точное поведение: что движок ждёт на входе
и что делает с этим на выходе.

---

## 1. Что такое тайл и откуда движок его берёт

- **Тайл** — обычный HTML-файл `tiles/*.html` (вшит в бинарник через `//go:embed`).
- **Страница** (роут) — набор тайлов. Какая страница, какие тайлы и где они стоят —
  описывается в `tiles.json` (контракт ниже).
- Движок при старте читает `tiles.json` и парсит HTML тайлов **один раз** (кэш);
  дальше каждый кадр рендерится из кэша — файлы повторно не читаются.

### Контракт `tiles.json` (чего ждёт движок)

```json
{
  "theme": "default",
  "menu": [["Главная", "/main"], ["Справка", "/man"]],
  "pattern": ["id", "x", "y", "w", "h", "file"],
  "/main": [
    ["hello", "0%",  "0%",  "40%", "40%", "tiles/hello.html"],
    ["cfg",   "40%", "0%",  "60%", "100%", "tiles/cfg.html"]
  ]
}
```

| Ключ | Что ожидает движок | Что делает |
|---|---|---|
| `theme` | имя темы из `themes/` (по умолчанию `default`) | активная тема |
| `menu` | массив пар `[имя, роут]` | вкладки внизу |
| `pattern` | массив из 6 имён полей | схема строк тайлов (можно не задавать — дефолт `id,x,y,w,h,file`) |
| `/роут` | массив массивов (6 значений по паттерну) | тайлы страницы |

Каждый тайл — массив из 6 значений по паттерну:
`["id", "x", "y", "w", "h", "file"]`:

- `id` — имя тайла (рисуется на рамке, используется в скролле);
- `x, y, w, h` — позиция и размер: `%` (от экрана), `px` (клетки), `vw/vh` (доли окна);
- `file` — путь к HTML внутри папки (относительный, например `tiles/hello.html`).

Движок сам растягивает тайлы под размер терминала (ресайз пересчитывает `%`).

## 2. Как движок читает HTML тайла

- HTML парсится (стандартный парсер HTML), движок обходит дерево тегов.
- **Любой текст рисуется как есть** — теги не обязательны.
- Для каждого известного тега — своё поведение (таблица в разделе 17).
- **Неизвестные теги** (`html`, `body`, `span` и т.п.) — не ломаются: движок просто
  обходит их содержимое.
- **Цвета** (`color` — текст, `bg` — фон, на любом элементе) понимают:
  - `hex` (`#ffcc00`) — жёсткий цвет;
  - номер палитры терминала (`"3"`) — терминал покажет свою перекрашенную палитру;
  - имя из темы (`"frame"`) — ссылка на ключ темы;
  - имя tcell (`"red"`) — имя палитры.

**Известные теги** (движок понимает; все остальные просто обходит):

| Тег | Поведение |
|---|---|
| текст | рисуется как есть |
| `<h1>` / `<p>` | заголовок (жирный) / абзац |
| `<br/>` | пустая строка |
| `<b>` / `<i>` | жирный / курсив |
| `<center>` | центрирует строку |
| `<div>` | блок |
| `<row>` | ряд колонок |
| `<hr/>` | линия |
| `<pre>` | моноширинный блок | 
| `<button>` `<a>` `<input>` `<checkbox>` `<select>` | кликабельные (разделы 4–10, 14) |
| `<table>` | таблица |
| `<img>` | картинка PPM |
| `<plugin>` | живой контент |

**Атрибуты (что понимает движок):** `action`, `output`, `href`, `label`, `options`,
`color`, `bg`, `width`, `align`, `id`, `interval`, `name`, `pipe`, `source`, `path`, `height`.

## 3. Интерактив: как движок понимает клики

У любого кликабельного элемента есть атрибут `action` — это **строка-команда**.
Движок при клике:

1. находит кликабельную зону;
2. берёт её `action`;
3. разбирает строку (имя + аргументы + пайп);
4. выполняет и показывает результат.

**Формат команды:** `имя:арг1:арг2` — имя до первого `:`, аргументы через `:`.
Пайп: `шаг1 | шаг2 | шаг3` — выход одного шага идёт на вход следующего.

**Параметры плагина — два способа (можно миксовать):**
- **как в Linux:** `name --flag=value` — именованные флаги, порядок не важен;
- **quick-параметры:** `имя:арг1:арг2` — по порядку, как определил разработчик плагина.

Правила quick-параметров:
- необязательный параметр пропускается пустым слотом `::` — `name::arg2`
  (берётся дефолт или не используется);
- конец строки параметров необязателен — `name:arg1` (арг2 не задан → дефолт/не используется);
- доступен микс: `name:arg1 --flag2=value`;
- ошибки при неправильной настройке показываются в статус-строке интерфейса.

**Куда идёт результат:**
- без `output` → в **статус-строку** внизу;
- с `output="id"` → в блок `<div id="id">` (см. раздел 7).

## 4. Кнопка `<button action="...">`

**Что ожидает:** атрибут `action` (обязательный), текст — подпись кнопки.

**Что делает:** рисует `⟨ подпись ⟩` и кликабельную зону. По клику выполняет `action`.

```html
<button action="hello">Поздороваться</button>
<button action="hello:мир">Поздороваться (с аргументом)</button>
<button action="cat:/etc/hostname">Показать hostname</button>
```

- `action="hello"` — вызвать плагин `hello` без аргументов.
- `action="hello:мир"` — вызвать `hello` с аргументом `мир`.
- Без `output` результат — в статус-строку.

---

## 5. Поле ввода `<input action="..." label="..." output="..."/>`

**Что ожидает:**
- `action` — команда, в конец которой приклеится ввод (**лучше с `:` в конце**);
- `label` — подпись поля (то, что видно до ввода);
- `output` — необязательно, куда направить результат.

**Как работает (точно):**
1. Клик по полю **активирует** его — ввод идёт прямо в поле (внутри рамки `[ ✎ … ]`).
2. Юзер печатает текст.
3. Enter — движок **склеивает строку**: `action` + `:` + ввод, и выполняет её как обычную команду.
4. Esc — отмена ввода.

То есть `<input action="man:">` + ввод `ssh` = выполняется строка `man:ssh`.
Если в `action` нет `:` на конце — движок добавит её сам (ввод всегда последний аргумент).

**Безопасность (защита от инъекций):** ввод из поля — всегда **одно значение**
(литерал). Движок оборачивает его в кавычки, поэтому спецсимволы `|`, `:`, `$`
внутри ввода НЕ интерпретируются как синтаксис action: `cat | ssh:...` останется
одним значением, а не пайпом — через поле ввода нельзя выполнить произвольную
команду. Ввод, содержащий кавычку `'`, отклоняется с ошибкой в статус-строке.

```html
<input action="man:" output="out" label="Пакет"/>            <!-- man:ssh, man:cat -->
<input action="set:/etc/app.conf:max_users:" label="Лимит"/> <!-- set:...:max_users:100 -->
<input action="export:маска" label="Маска"/>                  <!-- запомнить ввод -->
```

Ввод может быть только **одним** (последним) аргументом — остальные фиксированы в `action`.

---

## 6. Пайп `|` — передача данных между командами

**Контракт:** `шаг1 | шаг2 | шаг3`. Выход одного шага — вход следующего (как в шелле).

```html
<button action="cat:/var/log/app.log | tail:20">Хвост лога</button>
<button action="cat:/etc/x.conf | grep:^server | head:5">Серверы (5 шт)</button>
```

- `cat` отдаёт строки → `grep` их фильтрует → `head` режет.
- Если шаг вернул ошибку — пайп останавливается, ошибка в статус-строку.

## 7. Приёмник вывода `<div id="...">` и `output="id"`

**Контракт:** на любом действии (кнопка/поле/select) есть `output="id"`. Движок кладёт
результат в память под ключом `id`. Блок `<div id="id">` при отрисовке показывает эти строки.

- Приёмник можно ставить где угодно: в этом тайле, в соседнем, в другом роуте.
- Это **только отображение** — вывод в команды через это НЕ передаётся (для этого пайп `|`).

```html
<button action="man:ssh" output="out">Справка по ssh</button>
<!-- ... в другом тайле: -->
<div id="out"></div>
```

---

## 8. Переменные: `export:имя` и `$имя`

**Контракт:**
- `... | export:имя` — плагин сохраняет входящие строки в переменную движка и
  пропускает их дальше (как `tee`);
- `$имя` / `${имя}` в любом `action` — движок подставляет значение переменной
  **до** разбора команды;
- `\$` — буквальный доллар; неизвестная переменная — пустая строка.

Это «память» интерфейса: запомнил раз — используешь много.

```html
<button action="ssh:root:srv1::hostname | export:host">Запомнить</button>
<button action="ssh:root:$host::uptime">Uptime</button>
<input action="export:маска" label="Маска"/>
<button action="cat:log | grep:$маска | head:5">Найти</button>
```

## 9. Чекбокс `<checkbox action="...">`

**Что ожидает:** `action` вида `toggle:FILE:KEY`, текст — подпись.

**Как работает:** рисует `[x]` / `[ ]` + подпись.
- При отрисовке движок **спрашивает состояние**: вызывает `action` с дописанным
  `:get` (`toggle:file:key:get`) — плагин возвращает текущее значение, движок
  рисует галочку.
- По клику выполняет `action` — плагин переключает (0↔1 / on↔off / true↔false).

```html
<checkbox action="toggle:app.conf:debug">Отладка</checkbox>
<checkbox action="toggle:/etc/app.conf:logging">Логирование</checkbox>
```

---

## 10. Выпадающий список `<select action="..." options="..." label="..."/>`

**Что ожидает:**
- `action` — команда, к которой допишется выбранный вариант (`:` + вариант);
- `options` — варианты через `:` (подменю — `Метка [дети:варианты]`);
- `label` — подпись.

**Как работает:** рисует `label ▼ текущее`. Клик/Enter открывают меню **справа**.
Выбор варианта → выполняется `action` + `:` + вариант.

```html
<select action="set:/etc/app.conf:loglevel" options="info:debug:trace" label="Уровень"/>
<!-- выбрал debug → выполнится set:/etc/app.conf:loglevel:debug -->
```

- Текущее значение движок показывает, спросив `action:get` (как у checkbox).
- Esc/клик мимо — закрыть. Подменю — `[дети:...]`, открывается вправо.

---

## 11. Таблица `<table>`

**Что ожидает:** `<tr>` со строками, ячейки `<td>` (обычные) и `<th>` (жирный заголовок).

**Как работает:** колонки выравниваются по самой широкой ячейке, между ними `│`.

```html
<table>
  <tr><th>Сервис</th><th>Статус</th></tr>
  <tr><td>api</td><td>работает</td></tr>
  <tr><td>db</td><td>работает</td></tr>
</table>
```

---

## 12. Картинка `<img src="..."/>`

**Что ожидает:** `src` — путь к файлу **PPM P6** (бинарный) на диске.

**Как работает:** читает файл, рисует половинчатыми блоками `▀▄█` с цветами.
Масштаб — по ширине тайла/колонки. Формат только PPM P6.

```html
<img src="/opt/app/logo.ppm"/>
```

## 13. Живой контент `<plugin .../>`

**Что ожидает:** либо `name`, либо `pipe` (пайп), и `interval` (как часто обновлять).

| Атрибут | Что делает |
|---|---|
| `name="clock"` | запустить плагин по имени (без входа) |
| `pipe="a | b"` | запустить пайп |
| `source="..."` / `path="..."` | источник: `file:ПУТЬ` (или путь) — входит первым шагом |
| `mask` | (устарело) маска регуляркой для numbers-плагинов |
| `interval="1s"` | как часто перезапускать (не задан → 2с) |
| `height="14"` | высота зоны (для chart) |

**Как работает:** плагин выполняется, результат рисуется; кэш не запускает его
чаще `interval`. Обновление — по таймеру главного цикла.

```html
<plugin name="clock" interval="1s"/>
<plugin pipe="emu_cpu | chart:0:100:1:2:CPU" height="14" interval="2s"/>
<plugin pipe="cat:data.log | tail:10 | bars" interval="2s"/>
```

`chart` — живой столбчатый график (ось справа). Параметры: `chart:MIN:MAX[:WIDTH[:SECONDS[:TITLE]]]`
или флагами `chart --min=0 --max=100 --title=CPU`, можно микс. Ширина — из тайла/колонки.

## 14. Ссылки `<a href="/роут">`

**Что ожидает:** `href` — роут, **который существует** в `tiles.json` (иначе
проверка синтаксиса не даст стартовать).

**Как работает:** рисует `→ текст`; клик переключает страницу.

```html
<a href="/main">← На главную</a>
```

## 15. Скролл

Контент длиннее тайла — скроллится **колесом мыши**. Справа полоса прокрутки.
Кнопки/поля/хотзоны сдвигаются вместе с контентом — всё остаётся кликабельным.
Ничего настраивать не нужно.

---

## 16. Подтверждение `| confirm`

`| confirm` в конце пайпа — движок покажет окно «Выполнить?» (Enter — да, Esc — нет).

```html
<button action="deploy:all | confirm">Раскатать прод</button>
<button action="ssh:root:srv1::reboot | confirm">Перезагрузить</button>
```

---

## 17. Кавычки: значение с `:`

Аргументы разделяются `:`. Если значению нужна `:` — оберни в кавычки `'...'`
или `"..."`: внутри кавычек `:` — обычный символ, кавычки снимаются.

```html
<button action="sed:':':1">Заменить ":" на "1"</button>
<button action="cut --sep=':' --fields=1">Первое поле по ":"</button>
```

## 18. Шпаргалка: теги, что ожидают и что делают

| Тег | Что ожидает | Что делает |
|---|---|---|
| текст | — | рисует как есть |
| `<h1 color>` / `<p>` | текст | заголовок (жирный) / абзац |
| `<br/>` | — | пустая строка |
| `<b>` / `<i>` | текст | жирный / курсив |
| `<center>` | текст | центрирует строку |
| `<div>` | текст/теги | блок |
| `<div width="%">` | внутри `<row>` | колонка |
| `<div align="center">` | теги | блок по центру (гор. и верт.) |
| `<div id="id">` | — | приёмник вывода (`output="id"`) |
| `<row>` | `<div width>` | ряд колонок |
| `<button action>` | action, текст | кнопка-вызов |
| `<input action label output>` | action (`:` в конце), label | поле ввода (ввод → последний аргумент) |
| `<checkbox action>` | `toggle:file:key` | чекбокс [x]/[ ], клик переключает |
| `<select action options label>` | action, options, label | выпадающий список |
| `<table><tr><th>/<td>` | строки/ячейки | таблица |
| `<img src>` | путь к PPM P6 | картинка |
| `<hr/>` | — | линия |
| `<pre>` | текст | моноширинный блок (не ломает пробелы) |
| `<a href>` | роут из tiles.json | ссылка-переход |
| `<plugin name/pipe interval>` | name или pipe, interval | живой контент по таймеру |
| `output="id"` | на кнопке/поле/select | куда направить результат |
| `| confirm` | в конце пайпа | окно подтверждения |

## 19. Частые вопросы

**Что будет без `output="id"`?** Результат уйдёт в статус-строку внизу.

**`output` передаёт данные в команду?** Нет. `output` — только куда показать.
Данные между командами передаёт пайп `|`, между кнопками — `export`/`$`.

**Почему у поля ввода `:` в конце action?** Потому что ввод приклеивается к action
как последний аргумент: `man:` + `ssh` = `man:ssh`. Без `:` движок добавит её сам.

**Почему у `ssh` команда после `::`?** `ssh:user:host::команда` — порт пустым слотом
(дефолт 22). Подробнее — раздел SSH в этом файле.

**У меня не работает кириллица.** Терминал должен быть UTF-8: Windows — `chcp 65001`
или Windows Terminal / VS Code.
