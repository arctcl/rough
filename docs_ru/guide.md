# Кукингбук: rough от простого к сложному

Единый гайд: как устроен движок, как писать тайлы и HTML, как собирать команды.
Идём от самого простого («вот так пишется тайл») до сложного («вот так пайплайн
на 50 операторов для кнопки, перезагружающей ядерный реактор»). Каждый раздел —
короткое объяснение и готовый пример.

> формы диапазонов) — в [`reference.md`](reference.md); архитектура — в

## 1. Что такое rough

Движок рисует страницы, на них раскладывает тайлы, а внутри тайлов располагает
обычный HTML — и интерфейс готов. Ты не пишешь код интерфейса и не собираешь
окна: ты пишешь HTML, а движок превращает его в клетки терминала и реагирует на
клики. Кнопка в HTML несёт команду, клик по кнопке выполняет команду, а её
результат показывается на экране — внизу в статус-строке или в блоке вывода.

Интерфейс делится на **страницы** (роуты). Каждая страница — это набор **тайлов**,
прямоугольников с HTML внутри. Какие страницы есть, какие тайлы на них стоят и
где — всё это описывается в одном файле `tiles.json`.

## 2. Вот так пишется тайл (tiles.json)

Одна страница из двух тайлов — слева настройки, справа вывод:

```json
{
  "theme": "default",
  "menu": [["Главная", "/main"]],
  "/main": [
    ["cfg", "0%", "0%", "40%", "100%", "tiles/cfg.html"],
    ["out", "40%", "0%", "60%", "100%", "tiles/out.html"]
  ]
}
```

Ключ `theme` задаёт тему из папки `themes/` (по умолчанию — `default`). Ключ
`menu` описывает вкладки внизу экрана: каждая вкладка — пара «подпись и роут».
Дальше идут страницы: имя роута (например `/main`) и список его тайлов.

Каждый тайл — это массив из шести значений: `[id, x, y, w, h, file]`. `id` — имя
тайла (видно на рамке). `x`, `y`, `w`, `h` — позиция и размер: проценты от экрана
(`%`), клетки (`px`) или доли окна (`vw`/`vh`). `file` — путь к HTML-файлу тайла.
Движок сам растягивает тайлы под размер терминала: изменил окно — проценты
пересчитались, и ничего не поплыло.

Несколько страниц и вкладки внизу:

```json
{
  "menu": [
    ["Главная", "/main"],
    ["Настройки", "/cfg"]
  ],
  "/main":  [["main", "0%", "0%", "100%", "100%", "tiles/main.html"]],
  "/cfg":   [["cfg",  "0%", "0%", "100%", "100%", "tiles/cfg.html"]]
}
```

Тайл, растягивающийся при изменении окна (проценты), и тайл фиксированного
размера (клетки):

```json
["panel", "0%", "0%", "100%", "100%", "tiles/panel.html"]
["side",  "0",   "0",  "40",   "20",   "tiles/side.html"]
```

## 3. Вот так пишется HTML (текст и разметка)

Всё, что написано в HTML тайла, рисуется как есть — теги делают текст
осмысленным. Заголовок, абзац, пустая строка, жирный и курсив, центрирование,
линия и моноширинный блок:

```html
<h1>Заголовок</h1>
<p>Обычный абзац.</p>
<br/>                  <!-- пустая строка -->
<b>жирный</b> <i>курсив</i>
<center>по центру</center>
<div>блок текста</div>
<hr/>                  <!-- линия -->
<pre>
   моноширинный блок
   пробелы сохраняются
</pre>
```

Блок `<div>` умеет группировать текст, а `<row>` выстраивает блоки-колонки в ряд:

```html
<row>
  <div width="50%">левая колонка</div>
  <div width="50%">правая колонка</div>
</row>
```

Цвет — атрибутом `color` для текста и `bg` для фона. Можно ввести hex
(`#rrggbb`), номер палитры терминала (`3`) или имя из темы (`header_bg`):

```html
<h1 color="#ffcc00">Жёлтый заголовок</h1>
<p bg="4">Синий фон из палитры</p>
<p color="color_2">зелёный текст</p>
<p bg="header_bg">цвет из темы</p>
```

## 4. Вот так кнопка (action)

Кнопка вызывает **команду** — ровно как команда в Linux. Формат простой:
`имя:арг1:арг2` или `имя --arg=value`. Имя — это плагин, аргументы отделяются
двоеточием или флагами:

```html
<button action="hello">Поздороваться</button>
<button action="hello:мир">Поздороваться, мир</button>
<button action="cat:/etc/hostname">Показать hostname</button>
```

Первая кнопка вызывает плагин `hello` без аргументов. Вторая — тот же `hello`,
но с аргументом `мир`. Третья — плагин `cat` с путём к файлу: `cat` читает файл
с диска и отдаёт его содержимое.

Параметры можно задавать и флагами, как в Linux (`cat --file=/x`), и
quick-позиционно, через двоеточие. Что именно принимает плагин, определяется
самим плагином, а узнать это всегда можно через справку: кнопка
`action="man:имя"` покажет описание.

Результат команды без атрибута `output` показывается в статус-строке внизу
экрана.

## 5. Вот так кнопка с подтверждением (confirm)

Опасное действие (перезагрузка, удаление) стоит подвесить на подтверждение:
`| confirm` в конце команды открывает окно — Enter «да», Esc «нет»:

```html
<button action="ssh:root:srv::reboot | confirm">Перезагрузить</button>
<button action="ssh:root:srv1::apt update && apt upgrade -y | confirm">Обновить</button>
```

> [!WARNING]
> `| confirm` не отменяет действие — он лишь просит подтверждение. Думай, что выполняешь, перед Enter.

## 6. Вот так рисуночек и таблица

Таблица собирается из строк `<tr>` и ячеек `<td>` (обычные) и `<th>` (заголовок).
Колонки сами выравниваются по самой широкой ячейке, так что таблица всегда ровная:

```html
<table>
  <tr><th>Сервис</th><th>Статус</th></tr>
  <tr><td>api</td><td>работает</td></tr>
  <tr><td>db</td><td>работает</td></tr>
</table>
```

Картинка рисуется из файла формата PPM P6 — половинчатыми блоками, по два
пикселя на клетку терминала. Достаточно указать путь в `src`:

```html
<img src="/opt/app/logo.ppm"/>
```

Ссылка переключает страницу на другой роут — так делают навигацию:

```html
<a href="/main">← На главную</a>
```

## 7. Вот так пайп

Пайп `|` соединяет команды в цепочку: вывод одной команды идёт на вход следующей,
как в шелле. Например, взять хвост лога или отфильтровать строки конфига:

```html
<button action="cat:/var/log/app.log | tail:20">Хвост лога</button>
<button action="cat:/etc/x.conf | grep:^server | head:5">Серверы (5)</button>
```

Здесь `cat` читает файл и отдаёт строки, `grep` оставляет только нужные, а `head`
режет до первых пяти. Первый плагин может быть «источником» — сам добывать
данные, например по ssh:

```html
<button action="ssh:root:srv::uptime | head:3">Аптайм</button>
```

Если на каком-то шаге случилась ошибка — пайп останавливается, а сообщение об
ошибке показывается в статус-строке.

## 8. Вот так несколько пайпов (`&&` и `clear`)

Одна кнопка может запустить несколько НЕЗАВИСИМЫХ пайпов подряд — через `&&`.
Каждый `&&`-кусок выполняется отдельно (не как конвейер выход→вход), а результаты
**склеиваются** в один блок вывода (как `cat a b`):

```html
<button action="clear && man:ssh && cat:/etc/hosts">Справка + hosts</button>
```

- `clear` очищает блок вывода и включает режим склейки (начинает с чистого листа);
- следующие пайпы **добавляют** свой вывод к блоку, а не перезаписывают его.

Без `clear` несколько пайпов тоже выполнятся, но в приёмник попадёт результат
последнего (предыдущие перезапишутся).

## 9. Вот так переменные

`export` и `unexport` — **резервные слова движка** (не плагины): переменные
собирает и хранит сам движок. Переменная, записанная через `export`, **доступна
всегда и отовсюду**: из любой кнопки, поля, тайла и даже из другого `&&`-пайпа.
`$имя` подставляется в момент выполнения шага, а не при разборе действия,
поэтому `export` из раннего пайпа успевает записать значение до того, как
поздний его прочитает.

Запомнить результат и подставить позже:

```html
<button action="ssh:root:srv1::hostname | export:host">Запомнить</button>
<button action="ssh:root:$host::uptime">Uptime на $host</button>
```

Использовать переменную из другого `&&`-пайпа:

```html
<button action="cat:data.log | wc:lines | export:n
  && hello:строк $n" >Сколько строк</button>
```

Удалить переменную — `unexport` (антипод `export`):

```html
<button action="... | export:tmp | ... | unexport:tmp">временная</button>
```

Отделить имя переменной от соседей — `${имя}`; убрать суффикс/префикс — как в
bash (`${f%.log}`, `${f#/var/}`); литеральный `$` — `\$`; не подставлять вовсе —
кавычки `'$имя'`.

**Аккумулятор.** Обычный `export:имя` перезаписывает переменную при каждом
вызове — в многошаговом пайпе останется только последнее число, а суммы по
кускам не будет. Форма `export:ИМЯ +=` заставляет движок **прибавлять** число к
текущему значению. Число берётся из текущего вывода пайпа (кусок) либо задаётся
явно (`export:count += 5`). Движок сам складывает — плагин `wc` только считает
строки одного куска:

```html
<button action="clear
  && cat:log.txt | line:0-499  | wc:lines | export:count +=
  && cat:log.txt | line:500-999 | wc:lines | export:count +=
  && cat:log.txt | line:1000-1499 | wc:lines | export:count +=
  && hello:всего строк $count" >Сумма по кускам</button>
```

(Напомним: `line` читает файл целиком — «куски» лишь разбиение на итерации,
не экономия памяти.)

## 10. Вот так диапазоны и циклы

Диапазон в квадратных скобках разворачивается в перебор: команда выполняется
на каждом значении, выводы склеиваются. Так обновляют флот серверов:

```html
<button action="ssh:root:192.168.1.[1-250]:apt upgrade" output="out">Обновить все</button>
```

`[1-250]` → `192.168.1.1 … 192.168.1.250`.

Также поддерживаются:
- шаг `[N-M:S]`: `[0-1000:100]` → `0,100,200,…,1000`;
- буквы `[a-c]` → a, b, c;
- список `[1,4,9]`;
- несколько диапазонов сразу (декартово произведение): `192.168.[1-2].[1-2]` → 4 адреса.

Диапазон может держать переменную: `[0-$n:500]` раскрывается в момент выполнения
шага (после подстановки `$n` в число), а не на старте, когда переменная ещё пуста.

Содержимое в `[...]`, которое не похоже на диапазон (например `[foo]`), не
трогается — остаётся как есть.

**Цикл `loop:N`** — ключевое слово: запускает остальные шаги пайпа N раз и
склеивает выводы. `$count` уже раскрыт в число, так что команда выполнится
ровно столько раз:

```html
<button action="clear && cat:lev_tolstoy.txt | wc:lines | export:ln_sum
  && line:[0-$ln_sum:500] | grep:$in | wc:lines | export:count
  && loop:$count | ssh:root:127.0.0.1:22:sl" label="Слово" output="out">Слово</button>
```

`loop:1` — как без цикла.

## 11. Вот так квик-параметры (контракт плагина)

Каждый плагин сам задаёт, какие параметры он принимает и в каком порядке — это
**контракт плагина**. Движок даёт лишь общий механизм ввода: параметры можно
передать **позиционно** (через двоеточие, по порядку) или **флагами** (`--имя=значение`),
а можно смешивать.

Позиционно — по порядку:

```text
chart:0:100:1:2:CPU
```

Пропустить параметр (берётся дефолт) — пустой слот `::` (да, как в ipv6):

```text
chart:0:100::2:CPU
```

Флагами — порядок не важен:

```text
chart --min=0 --max=100 --title=CPU
```

Смешать слоты и флаги:

```text
chart::100 --title=CPU
```

Значение, в котором есть `:` или `|`, — берётся в кавычки:

```text
sed:':':1
```

Последний параметр «глотает» остаток двоеточий — так передают команду с
произвольным хвостом:

```text
ssh:user:host:67:docker compose down && up
```

Что именно принимает конкретный плагин и какие у него дефолты — смотрится через
`man:имя` (кнопка `action="man:имя"`).

> [!IMPORTANT]
> Контракт параметров у каждого плагина свой: движок даёт лишь два способа ввода
> (позиционно и флагами), а что за параметры и какие дефолты — у каждого свои,
> всегда через `man:имя`.

## 12. Вот так поля, чекбоксы и select

Поле ввода собирает команду из своего `action` и текста, который введёт юзер.
Клик по полю активирует его, юзер печатает, жмёт Enter — и движок склеивает
`action` с вводом через двоеточие. Ввёл `ssh` в поле с `action="man:"` —
выполнится `man:ssh`:

```html
<input action="man:" label="Пакет"/>   <!-- ввёл ssh → man:ssh -->
```

Ввод можно подставить в конкретное место пайпа через `$in`, а если `$in` нет —
ввод уходит «входом» первому плагину:

```html
<input action="grep:$in | sort" label="Шаблон"/>
<input action="cat | grep | sort" label="Данные"/>
```

Esc отменяет ввод.

> [!IMPORTANT]
> Ввод из поля — всегда одно значение. Движок оборачивает его в кавычки, поэтому
> `|`, `:`, `$` внутри ввода не работают как синтаксис: ввести `cat | ssh:...`
> через поле нельзя — это останется обычным текстом, а не командой.

Чекбокс — галочка: клик переключает значение ключа в файле (0↔1, on↔off):

```html
<checkbox action="toggle:app.conf:logging">Логирование</checkbox>
```

Выпадающий список — выбор одного значения из набора; выбранный вариант
дописывается к команде:

```html
<select action="set:app.conf:loglevel" options="info:debug:trace" label="Уровень"/>
```

Списки умеют вложенность: вариант с подменю записывается как
`Метка [дети:варианты]`:

```html
<select action="set:app.conf:theme"
        options="Тёмная:Светлая:Цветная [Красная:Зелёная:Синяя]" label="Тема"/>
```

Если конфиг не в формате `ключ=значение`, а через пробел — добавь флаг
`--sep=space` (для `toggle` и `set`):

```html
<checkbox action="toggle:/etc/mailcow:debug --sep=space">Отладка</checkbox>
```

## 13. Вот так живой контент (plugin)

Тег `<plugin>` обновляет себя сам, по таймеру — без всяких кликов. Интервал
задаётся атрибутом `interval` (не задал — две секунды). Так в тайле живут часы,
график нагрузки или спарклайн:

```html
<plugin name="clock" interval="1s"/>                   <!-- часы -->
<plugin pipe="emu_cpu | chart:0:100:1:2:CPU" height="14" interval="2s"/>
<plugin pipe="cat:data.log | tail:10 | bars" interval="2s"/>
```

`chart` — живой столбчатый график с осями. Его параметры идут через двоеточие:
`chart:MIN:MAX[:WIDTH[:SECONDS[:TITLE]]]` — диапазон обязателен, остальное по
умолчанию. Высота — из `height`, ширина — из тайла, так что график сам
подстраивается под место.

Медленный источник (например ssh) — запускай как `async`, чтобы не морозить
интерфейс:

```html
<plugin pipe="ssh:host::vmstat | cut::2" interval="1s" async/>
```

## 14. Вот так куда идёт результат (output)

Результат команды можно показать двумя способами. Без атрибута `output`
результат уходит в статус-строку внизу. Если указать `output="id"` — результат
попадёт в блок `<div id="id">`, и этот блок может лежать где угодно: в этом
тайле, в соседнем или на другой странице:

```html
<button action="man:ssh" output="out">Справка по ssh</button>
<!-- в любом тайле: -->
<div id="out"></div>
```


## 16. Всё вместе: панель

Соберём маленькую панель: одна страница, слева тайл с настройками, справа — тайл
вывода. Начинается всё с `tiles.json`:

```json
{
  "theme": "default",
  "menu": [
    ["Панель", "/main"],
    ["Справка", "/man"]
  ],
  "/main": [
    ["cfg", "0%", "0%", "40%", "100%", "tiles/cfg.html"],
    ["out", "40%", "0%", "60%", "100%", "tiles/out.html"]
  ],
  "/man": [
    ["man", "0%", "0%", "100%", "100%", "tiles/man.html"]
  ]
}
```

В тайле настроек живут чекбокс, выпадающий список, поле ввода, кнопки с
подтверждением и живой график:

```html
<h1 color="color_2">Панель</h1>

<checkbox action="toggle:app.conf:debug">Отладка</checkbox>
<select action="set:app.conf:loglevel" options="info:debug:trace" label="Уровень"/>

<input action="man:" output="out" label="Справка по плагину"/>

<button action="cat:app.conf" output="out">Показать конфиг</button>
<button action="clear && man:ssh && cat:app.conf" output="out">Справка + конфиг</button>
<button action="ssh:root:srv::reboot | confirm">Перезапустить</button>

<plugin pipe="emu_cpu | chart:0:100:1:2:CPU" height="10" interval="1s"/>
<plugin pipe="ps --track=1" interval="1s" async/>

<hr/>
<button action="ssh:root:srv::hostname | export:host">Запомнить хост</button>
<button action="ssh:root:$host::uptime" output="out">Uptime на $host</button>

<a href="/man">Справка →</a>
```

А в `tiles/out.html` — просто заголовок и приёмник вывода:

```html
<h1>Вывод</h1>
<div id="out"></div>
```

Готово: кнопки меняют конфиг, чекбоксы переключают флаги, а результат любой
команды показывается в правом тайле.
